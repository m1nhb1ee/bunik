📐 Chuẩn hóa 2NF — Recap & Extended Fix

2NF yêu cầu: đã đạt 1NF + không có partial dependency. Mọi non-key attribute phải phụ thuộc vào toàn bộ khóa chính. v3.0 đã fix MAJORS, v4.0 extends thêm UNIVERSITY_PROGRAMS.

🔴 Vi phạm 2NF đã fix ở v3.0: Bảng MAJORS

Bảng MAJORS có composite key logic (university_id, code) nhưng major_name chỉ phụ thuộc code — partial dependency. Mã 7480201 luôn là "Công nghệ thông tin" dù ở trường nào.

❌ Trước — Vi phạm 2NF

-- major_name phụ thuộc code, KHÔNG university_id MAJORS ├── id (PK) ├── university_id (FK) ─┐ ├── code: "7480201" ─┤→ composite key ├── name: "CNTT" ← phụ thuộc code only! └── description ← phụ thuộc code only! -- 88 trường → lưu "CNTT" 88 lần -- Redundancy + Update anomaly
→

✅ Sau v3.0 — 2NF Compliant

MAJOR_CATALOG -- Danh mục quốc gia ├── id (PK) ├── code: "7480201" (UNIQUE) ├── name: "Công nghệ thông tin" ├── field_id (FK → FIELDS) └── description -- Mỗi mã ngành CHỈ xuất hiện 1 lần UNIVERSITY_MAJORS -- v3 junction ├── id (PK) ├── university_id (FK) └── major_catalog_id (FK)

🔴 Vấn đề nghiêm trọng phát hiện sau v3.0: UNIVERSITY_MAJORS không model được thực tế

UNIQUE(university_id, major_catalog_id) giả định mỗi trường chỉ có 1 chương trình cho mỗi mã ngành. Nhưng Bách Khoa Hà Nội có IT1, IT2, ICT đều thuộc mã 7480201 — mỗi chương trình có điểm chuẩn riêng. UNIQUE constraint này vi phạm business rule.

-- Constraint này block data thực tế: UNIVERSITY_MAJORS ├── id UUID (PK) ├── university_id (FK BKA) └── major_catalog_id (FK 7480201) -- Chỉ lưu được 1 dòng cho BKA × 7480201 -- IT1, IT2, ICT → không thể INSERT! -- UNIQUE(university_id, major_catalog_id) -- ↑ breaks on row 2 → ERROR
→

📏 Chuẩn hóa 3NF — Phân tích toàn bộ Schema

3NF yêu cầu: đã đạt 2NF + không có transitive dependency. Với mọi FD X → Y, X phải là superkey (hoặc Y là phần của candidate key). Scan từng bảng, từng FD.

🔍 Định nghĩa: Transitive Dependency

-- Vi phạm 3NF: PK → non-key A → non-key B -- Ví dụ vi phạm (KHÔNG có trong schema này): BAD_TABLE ├── id (PK) ├── province_id → region ← transitive! province_id không phải PK └── region ← phụ thuộc province_id, không phải id -- Khi thiết kế, 2 nguy hiểm lớn nhất đã được TRÁNH: -- (1) Không lưu region trong UNIVERSITIES → tránh id→province_id→region -- (2) Không lưu catalog_name trong UNIVERSITY_PROGRAMS → tránh id→major_catalog_id→name

📊 View 1: v_admission_overview

Flatten toàn bộ — expose internal_code, internal_name, program_type cho API. Fix UNIQUE INDEX dùng _id thay vì text column.

CREATE MATERIALIZED VIEW v_admission_overview AS SELECT -- University u.id AS university_id, u.name AS university_name, u.short_name, u.type AS university_type, p.name AS province, p.region, -- Program (NEW — từ UNIVERSITY_PROGRAMS) up.id AS university_program_id, up.internal_code, up.internal_name AS program_name, up.program_type, -- Major catalog mc.id AS major_catalog_id, mc.code AS major_code, mc.name AS major_name, f.name AS field_name, -- Score s.year, s.score, s.quota, am.code AS admission_method_code, am.name AS admission_method, s.note FROM admission_scores s JOIN university_programs up ON up.id = s.university_program_id JOIN universities u ON u.id = up.university_id JOIN provinces p ON p.id = u.province_id JOIN major_catalog mc ON mc.id = up.major_catalog_id JOIN fields f ON f.id = mc.field_id JOIN admission_methods am ON am.id = s.admission_method_id WHERE up.is_active = TRUE AND u.is_active = TRUE; -- FIX: Index dùng _id (INT) thay vì text "admission_method" CREATE UNIQUE INDEX ON v_admission_overview (university_program_id, admission_method_code, year); CREATE INDEX ON v_admission_overview (year DESC, score DESC); CREATE INDEX ON v_admission_overview (province, university_type); CREATE INDEX ON v_admission_overview (field_name); CREATE INDEX ON v_admission_overview (program_type);

📈 View 2: v_university_stats — FIX correlated subquery

v3.0 dùng (SELECT MAX(year) FROM admission_scores) inline — correlated subquery chạy mỗi row. v4.0 dùng CTE để evaluate 1 lần duy nhất.

CREATE MATERIALIZED VIEW v_university_stats AS -- FIX: CTE thay correlated subquery — evaluate MAX(year) đúng 1 lần WITH latest_year AS ( SELECT MAX(year) AS yr FROM admission_scores ) SELECT u.id, u.name, u.short_name, u.type, p.name AS province, p.region, COUNT(DISTINCT up.major_catalog_id) AS total_majors, COUNT(DISTINCT up.id) AS total_programs, ROUND(AVG(s.score), 2) AS avg_score, MIN(s.score) AS min_score, MAX(s.score) AS max_score FROM universities u JOIN provinces p ON p.id = u.province_id LEFT JOIN university_programs up ON up.university_id = u.id AND up.is_active = TRUE LEFT JOIN admission_scores s ON s.university_program_id = up.id AND s.year = (SELECT yr FROM latest_year) WHERE u.is_active = TRUE GROUP BY u.id, u.name, u.short_name, u.type, p.name, p.region;
📌 Thêm total_programs (số chương trình, khác total_majors số mã ngành) — hữu ích với trường như BKA có nhiều chương trình/ngành
